# CertVault 代码评审（v1.3 桌面版）

已读：app/core.js、store.js、app.js、excel.js、bridge.js、index.html、build/pack/CertVault.cs、HostBridge.cs、tests/。

## A. 最该改的 5 条

**A1 导入会把密码/网址/账户写成空（P0）**
- 现象：Excel 里「密码」「CA口令」列存在但单元格为空时，导入后原密码被清空；「网址/账户」同理，账户被清空后去重键从 `url|account` 变成 `url|`，下次再导入同一条会新增重复记录。
- 根因：app/core.js:379-380 `rec.password = pick('密码')` 无条件带 key（空串也带）；app/core.js:465-467 mergeImport 只跳过 null/undefined，空串照覆盖。
- 改法：fromCsv 对 password/caPassword/note 只在非空时赋值；mergeImport 对空串一律不覆盖（或给“允许用空值清空”的显式开关），url/account 尤其不能清。补 3 条单测（空密码、空账户、空网址）。
- 工时：0.5 天。

**A2 单写者锁是死代码（P0）**
- 现象：`data/.lock`、store.lock()/unlock()/lockInfo() 全项目无调用（grep 0 处）。两台机器或两个副本指向同一文件夹（共享盘/U 盘/NAS）时，后写者整文件覆盖前者，全程无提示。
- 根因：app.js 打开目录后只 readRecords，没走锁协议；CertVault.cs:36 的 Mutex 是会话级，只防同一用户开两个实例，防不了另一台电脑/另一个 Windows 账户。
- 改法：打开目录后立即 lock()（写 host+pid+时间），60s 心跳；发现他人未过期锁 → 只读模式 + 顶部横幅；退出/切换目录 unlock。store.js:567-604 已写好，只需接线。
- 工时：1 天。

**A3 删除先删图、后写库（P1）**
- 现象：写库失败（U 盘拔出、目录只读）时记录还在、images 目录已删，抽屉里全部“文件缺失”；backup 只存 JSON 不含图片，不可恢复。
- 根因：app/app.js:1702-1709 顺序是 deleteRecordImages → writeRecords。
- 改法：先写库（记录已移除），成功后再删图片目录。
- 工时：0.2 天。

**A4 写盘失败但界面已改（P1）**
- 现象：writeRecords 抛错时 state.records 已替换，列表显示“已保存/已删除”，重启发现回滚，用户以为数据在。
- 根因：app.js:1654、1708、1748 都是先改内存再写盘，catch 只 toast。
- 改法：先算 next 副本 → await write → 成功后再赋 state.records；失败保持旧状态并提示。
- 工时：0.3 天。

**A5「检查数据」形同虚设（P1）**
- 现象：设置页「检查数据」只重读 JSON + 数图片，孤儿图（手工拷入/删记录未删图）、引用缺失（images 目录被误删）、重复记录全都不报，用户得到“体检通过”的错觉。
- 根因：app.js:2210-2223 是 stub。
- 改法：双向比对 records↔images 目录，输出孤儿 N / 缺失 M / 重复 K 组，给一键清理与“重新关联”；结果写日志。
- 工时：0.5-1 天。

## C. 不建议改（避免过度设计）
- classic script + window.CVCore/CVStore：不是债，是 file:// 下唯一可行解；上打包器只会加构建链。
- host.json 原子写 + .bad 兜底：已经做好（HostBridge.cs:245-232），不用再动。
- 行体单击开抽屉（违背契约 §6.3）：用户实测认可，不回退。
- 序号不入库、派生状态：设计正确，别改成持久字段。
- 暂不拆 app.js：单人维护 + 无构建，拆分收益 < 风险；等上 NAS 网页端再按视图拆。
- 图片明文存目录：便携优先（拷走即用），加解密会破坏这个核心卖点。

**建议排期**：A1+A3+A4 半天一批（都是小改，直接消灭数据丢失路径），A2 一天，A5 一天；B 表按 P0→P1 递进。全部 A 组修完约 3 天，可发 v1.4。
