## 3. API 自动化验收摘要（套件 1 + 2）

### 3.1 端点覆盖 30 / 30

EP01–EP30 全部断言通过，覆盖健康检查、登录/登出、台账读写（If-Match 409）、settings、审计读写与筛选、图片增删读（multipart/304）、备份、锁、会话查询/续期、公共配置、注册与注册状态、管理员用户列表/审批/拒绝/改角色/启停/重置密码。端点覆盖表见 `.tmp/qa-t4-e2e.log` 末尾。

### 3.2 三角色越权矩阵

| 角色 | 断言结果 |
|---|---|
| viewer | 14 次请求（8 个 editor 级写接口 + 6 个 admin 接口）全部 403 `forbidden` |
| editor | 8 个业务写接口全部 200/201；6 个 admin 接口全部 403 |
| admin | 6 个用户管理接口全部 200/201；`PUT /api/records` 亦 200（admin 隐含 editor 权限） |

矩阵按超集执行：任务书要求 viewer 对 12 个写接口全部 403，当前契约中写路由共 13 个（editor 级 8 + admin 独占 5），另有 admin 读接口 1 个，脚本断言 14 条，无漏测。

### 3.3 注册 → 审批 → 角色生效 → 拒绝 → 停用

- 注册返回 `pending`；pending 登录 403 且提示等待审批；管理员用户列表可见且不泄露 `passHash`/`salt`。
- `approve{role:editor}` 后原密码可登录，`role=editor`；角色修改对同一 token 即时生效（viewer 403 → editor 200 → viewer 403）。
- `reject{reason}` 后登录 403 且携带中文原因；`status{disabled}` 后登录 403、既有 token 立即 401；`reset-password` 递增 tokenVersion 使旧 token 全部 401。

### 3.4 并发写（任务 ④）

- 2 个 token 同时 `PUT /api/records` 各 20 次，同一 `If-Match` ETag：**39 次 409、1 次 200**（要求 ≥19 次 409）。
- 无网络错误、无 5xx；最终台账可读、结构合法；磁盘 `certvault.json` 为合法 JSON；数据目录 **无 `.tmp` 残留**。

### 3.5 会话（任务 ⑤）

- `ttlSeconds=86400` 登录：token `exp-iat=86400`，`/api/session` 的 `ttlSeconds` 一致。
- 伪造已过期 token → 401；同一 secret 合法签名且未过期 token → 200（证明 401 来自过期判断，而非签名校验误杀）。
- `POST /api/session/extend{ttlSeconds:172800}` → 新 token 有效、`ttlSeconds=172800`、旧 token 仍可用。
- `POST /api/logout` → 该 token 立即 401，`Set-Cookie` 清除 `cv_token`。
