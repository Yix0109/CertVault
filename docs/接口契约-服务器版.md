# CertVault 服务器版 接口契约 v1（NAS 部署用）

> 本文件是 server/server.js 与 app/store-http.js 的唯一事实来源。两端必须严格按本契约实现，
> 不得自行改名、改路径、改错误码。改动契约必须先改本文件并通知 Lead。

## 1. 部署形态

- 单个容器：`node:20-alpine`，工作目录 `/srv`，入口 `node server.js`。
- 端口 `8080`（宿主机映射 8090）。
- 环境变量：`CV_DATA`（数据根，默认 `/data`）、`CV_PORT`（默认 8080）、`CV_USER`（默认 admin）、
  `CV_PASS`（首次启动用明文口令生成 hash，仅首次）、`CV_TZ`（默认 Asia/Shanghai）。
- 同一进程同时承担：静态站点（`/` 指向 `/srv/app`）+ REST API（`/api/*`）。
- 零第三方依赖：只用 `node:http`、`node:fs`、`node:path`、`node:crypto`、`node:url`、`node:os`。
- **禁止**使用 express/koa 等任何 npm 包；**禁止**引入编译期依赖。

## 2. 数据目录（与桌面版 数据\\ 完全同构，可直接拷贝）

```
$CV_DATA/
├── data/
│   ├── certvault.json     # {version:1, updatedAt:'ISO', records:[...]}
│   ├── settings.json      # 与桌面版 DEFAULT_SETTINGS 同结构
│   ├── audit.json         # {version:1, entries:[{at, action, detail}]}
│   └── .lock              # {owner, at}
├── images/<recordId>/<file>.png
├── backup/<yyyymmdd-HHmmss-reason>.json
├── users.json             # 账号表，见 §11
└── config.json            # {user, passHash, salt, createdAt, secret, sessionTtlSeconds, maxTtlSeconds, idleTimeoutSeconds}（权限 600）
```

## 3. 通用约定

- 请求体：`Content-Type: application/json`，UTF-8。
- 响应体：JSON，`Content-Type: application/json; charset=utf-8`。
- 成功：`200` + 业务 JSON。失败：HTTP 状态码 + `{error:{code,message}}`（message 必须是中文可读）。
- 错误码固定集合：`unauthorized`(401) / `forbidden`(403) / `not_found`(404) / `conflict`(409) /
  `payload_too_large`(413) / `bad_request`(400) / `internal`(500)。
- 认证（**双通道，token 为主体**）：`POST /api/login` 成功后同时返回 `token` 并下发 Cookie `cv_token`。
  - 客户端**优先用** `Authorization: Bearer <token>` 请求头（因为局域网 IP 与域名是不同 origin，Cookie 不共享，只有 Bearer 能跨地址复用登录态）。
  - 服务端先看 `Authorization`，没有再退回 Cookie `cv_token`；两者都无效 → 401 `unauthorized`。
  - token = base64url(JSON{u,role,iat,exp,jti}) + '.' + HMAC-SHA256(secret)；secret 存 `$CV_DATA/config.json`，首次启动随机生成，重启不变。
  - **会话有效期（桌面存活时间）可配置**：登录体可带 `ttlSeconds`，服务端用 `config.json` 的 `maxTtlSeconds` 夹紧；
    预设档位 1 天 / 7 天 / 30 天 / 永久（永久=3650 天）。缺省取 `config.json.sessionTtlSeconds`（默认 7 天）。
  - **空闲超时可选**：`config.json.idleTimeoutSeconds`（0=关闭，默认 0）。服务端按 token 里 `iat/exp` 与最近访问时间判断。
  - 除 `/api/health`、`/api/login`、`/api/register`、`/api/register/status`、`/api/config/public`、静态资源外，所有 `/api/*` 无有效 token 一律 401。
- 请求体上限：普通 JSON 2MB；台账整包 `PUT /api/records` 32MB；截图上传 80MB（8 张 × 8MB 再留余量）。超限一律 413 `payload_too_large`。
- 截图上传：单张 ≤8MB、单条记录累计 ≤8 张；超限的单个文件跳过并在 `skipped` 返回原因，不中断整批。
- 空闲超时（`idleTimeoutSeconds`）是**进程内滑动窗口**：最近访问时间只存在服务内存（重启归零），仅用于判断空闲；判定为空闲超时后会把该 token 写进 `data/revoked.json` 持久化吊销（重启后仍 401）。
- 写文件**必须原子**：先写 `path + '.tmp'`，再 `fs.renameSync(tmp, path)`；失败清理 tmp。
- 所有写 JSON 的请求在进程内串行执行（单条 Promise 队列），避免交错。
- 时间统一 ISO 8601 带时区（`new Date().toISOString()`）。

## 4. 端点清单

共 30 行 / **29 个唯一端点**：第 8 行与第 30 行都是 `GET /api/audit`（后者补充筛选参数与普通账号只看自己的口径），属同一端点重复列出。

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 1 | GET | `/api/health` | 免认证。返回 `{ok:true, name:'CertVault', version, records, images, uptime}` |
| 2 | POST | `/api/login` | body `{user, password}` → `{ok:true, role:'admin'|'editor'|'viewer'}` + Set-Cookie；失败 401 |
| 3 | POST | `/api/logout` | 清 Cookie，返回 `{ok:true}` |
| 4 | GET | `/api/records` | → `{version, updatedAt, records}`；文件不存在则返回 `{version:1, updatedAt:null, records:[]}` |
| 5 | PUT | `/api/records` | body `{updatedAt, records}`。请求头 `If-Match: <updatedAt|null>`；与服务端当前 updatedAt 不一致 → **409 conflict**（message『有人刚改过，请刷新后重试』）|
| 6 | GET | `/api/settings` | → settings.json 原文对象 |
| 7 | PUT | `/api/settings` | body 整个 settings 对象，整体覆盖 |
| 8 | GET | `/api/audit` | → `{version:1, entries:[...]}`（最多 200 条，最新在后）|
| 9 | POST | `/api/audit` | body `{action, detail}`（或数组），追加并裁剪到 200 条后返回 `{ok:true}` |

| 14 | POST | `/api/backups` | body `{reason}` → 把当前 records 复制到 `backup/<时间戳>-<reason>.json`，并执行『只留最近 10 份』，返回 `{ok:true, file, count}` |

| 19 | GET | `/api/session` | 当前会话：`{user, role, expiresAt, ttlSeconds, idleTimeoutSeconds}` |

| 21 | GET | `/api/config/public` | 免认证：`{name, version, serverTime, loginHint}`，用于地址探测与登录页展示 |

| 25 | POST | `/api/admin/users/{id}/approve` | 仅 admin。body `{role:'viewer'|'editor'|'admin'}` → 置 active |
| 26 | POST | `/api/admin/users/{id}/reject` | 仅 admin。body `{reason}` → 置 rejected |
| 27 | POST | `/api/admin/users/{id}/role` | 仅 admin。body `{role}` 改权限（不允许把最后一个 admin 降级）|
| 28 | POST | `/api/admin/users/{id}/status` | 仅 admin。body `{status:'active'|'disabled'}` |
| 29 | POST | `/api/admin/users/{id}/reset-password` | 仅 admin。body `{password}`，同时吊销该用户全部 token（改 `tokenVersion`）|

## 5. 静态站点

- `GET /` → `app/index.html`；`GET /<path>` → `app/<path>`（禁止 `..` 穿越）。

## 7. 桌面端（exe）模式切换

- `%LOCALAPPDATA%\\CertVault\\host.json` 增加可选字段 `serverUrl`（如 `http://192.168.1.10:8090`）。
- 有 `serverUrl` → 启动直接导航 `serverUrl + '/?server=1'`；无 → 现有本地文件夹模式（行为完全不变）。
- 服务器模式下的登录态由 WebView2 的 Cookie 持久化，关闭重开不需重新登录。

## 9. 多地址探测（局域网优先，桌面端必须实现）

同一套服务同时被两个地址访问：局域网 `http://192.168.x.x:8090`、外网/内网域名 `https://ca.example.com`。
客户端保存一个**地址簿**（数组，顺序=优先级），启动时按下述规则选地址：

1. 并行探测所有候选：`GET {base}/api/config/public`，超时 **1200ms**，任一条成功即记下往返耗时；
2. 其中 URL 主机是**私网地址**（10/8、172.16/12、192.168/16、127/8、*.local）且可达的，**优先选中**；
3. 无私网可达时，选延迟最低的公网/域名地址；全失败 → 进「离线/连接失败」页，展示每个地址的失败原因与「重试」。
4. 选中结果缓存 5 分钟；运行期任何请求出现网络级失败（非 4xx/5xx）→ 立刻标记该地址不可用并重新探测一次。
5. 地址簿存哪儿：网页版 localStorage(`cv.endpoints`)，桌面版 `host.json.endpoints`；单地址也走同一套代码（数组长度 1）。
6. 探测**不得**发认证请求，`/api/config/public` 与 `/api/health` 都是免认证的。

## 10. 登录与会话（前端行为）

- 登录体：`{user, password, ttlSeconds}`；成功后前端**立即把 token 写入** localStorage(`cv.token`) 或桌面 `host.json.session`，**不依赖 Cookie**。
- 「保持登录」勾选 + 时长下拉（1 天 / 7 天 / 30 天 / 永久）→ 就是 `ttlSeconds`。取消勾选 → `ttlSeconds=3600` 且关闭软件即清 token。
- 顶栏显示：地址来源徽标（🏠 局域网 / 🌐 域名）+ 账号 + 「会话剩余 6 天」。剩余 <1 天变金色，过期自动回登录页。
- 设置抽屉加「服务器」区：地址簿增删改、检测全部地址（显示每条的 ms 与结果）、会话时长、立即退出登录。

## 11. 账号、注册与审批（users.json）

```json
{
  "version": 1,
  "users": [
    { "id": "u_xxxxxxxx", "username": "admin", "displayName": "管理员",
      "passHash": "scrypt$...", "salt": "...", "tokenVersion": 1,
      "role": "admin", "status": "active",
      "device": "DESKTOP-01", "ip": "192.168.1.20",
      "createdAt": "ISO", "approvedAt": "ISO", "approvedBy": "u_admin1", "reason": null,
      "lastLoginAt": "ISO", "loginCount": 3 }
  ]
}
```

### 11.1 角色与权限矩阵（服务端强制，前端只做隐藏）

| 能力 | viewer（可查看+复制） | editor（可修改） | admin |
|---|---|---|---|
| 登录后读 records / settings / images / backups 信息 | ✅ | ✅ | ✅ |
| 在界面上复制密码 / CA 口令（客户端行为） | ✅ | ✅ | ✅ |
| 新增 / 编辑 / 删除记录 | ❌ 403 | ✅ | ✅ |
| 上传 / 删除截图 | ❌ 403 | ✅ | ✅ |
| 导入 / 导出（导出读数据，允许；导入写数据，403） | 导出✅ 导入❌ | ✅ | ✅ |
| 备份 / 改设置 / 加锁 | ❌ | ✅ | ✅ |
| 用户审批、改角色、停用、重置密码 | ❌ | ❌ | ✅ |
| 查看全员操作日志 | 只看自己最近 50 条 | 只看自己最近 50 条 | ✅ 全部 |

服务端在每个写接口入口做一次 `requireRole(req,'editor')` / `requireRole(req,'admin')`，越权统一 `403 forbidden` + 中文 message『当前账号只有查看权限，不能修改』。

### 11.2 首个管理员（bootstrap）

- 首次启动若 `users.json` 不存在：用环境变量 `CV_USER`（默认 `admin`）与 `CV_PASS` **必须非空**创建第一个 `role:'admin', status:'active'` 账号；`CV_PASS` 为空则**拒绝启动**并打印中文提示（避免裸奔）。
- 之后可在后台「用户管理」里新增/审批管理员，**不提供**通过接口把自己变成 admin 的路径。
- 至少保留一个 active 的 admin：降级/停用/删除最后一个 admin → 400 `bad_request`。

### 11.3 注册与审批流程

1. 桌面端登录页有「注册账号」按钮 → 填用户名/密码/设备名 → `POST /api/register` → 页面进入「等待管理员审批」状态，可每 5 秒轮询 `/api/register/status`。
2. 管理员在「用户管理」页看到 `pending` 列表（含设备名、IP、申请时间）→ 选角色后「同意」或「拒绝（填原因）」。
3. 通过后该用户用原密码登录即可；被拒/停用登录返回 403，message 带原因。
4. 防刷：同一 IP 10 分钟内最多 5 次注册尝试，超出 429 `bad_request`（message『注册过于频繁，请稍后再试』）；密码最短 6 位；用户名 3~32 位，只允许字母数字下划线短横线。

## 12. 审计日志（audit.json）

每条写入：`{at, userId, username, role, action, target, detail, ip, ok, ms}`。
- `action` 固定取值：`login` / `login_failed` / `logout` / `record_add` / `record_edit` / `record_delete` / `record_import` / `record_export` / `image_add` / `image_delete` / `settings_update` / `backup_create` / `user_register` / `user_approve` / `user_reject` / `user_role` / `user_status` / `user_reset_password` / `password_change`。
- 服务端**自己记**关键动作（login/logout/user_*/record_import 等），客户端可额外 `POST /api/audit` 补充细粒度动作；服务端写入时以 token 里的身份为准，**不信任客户端传的 userId**。
- 保留最近 5000 条（原来是 200 条，多用户后放宽），超出按时间裁剪；`GET /api/audit` 默认返回最近 200 条。
