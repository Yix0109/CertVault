# CertVault 服务器版验收清单（自动化 E2E）

> 依据：`docs/接口契约-服务器版.md` 第 8 节验收口径 + 任务 t8。
> 脚本：`scripts/e2e-server.mjs`（Node 内置 fetch，零第三方依赖，Node ≥ 20）。
> 定位：服务器 API 的端端自动化验收。浏览器界面（登录页、台账渲染、搜索、新增记录、上传截图、导出 xlsx）由 t4 用 Edge headless 单独验收，不在本脚本范围。

## 1. 运行方式

```bash
# 默认：脚本自行拉起 server/server.js（127.0.0.1:8090，临时数据目录，跑完自动清理）
node scripts/e2e-server.mjs

# 指向已运行的服务器（NAS / 容器 / 开发机）
CV_BASE=http://127.0.0.1:8090 node scripts/e2e-server.mjs
```

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `CV_BASE` | 空（自启 8090） | 设置后不启子进程，直接测该地址 |
| `CV_DATA` | 空 | 服务端数据根目录；设置后可断言磁盘 JSON 与 `.tmp` 残留、可读 `config.json` 做 token 伪造对照 |
| `CV_USER` / `CV_PASS` | `admin` / `e2e-admin-123` | 首个管理员账号；自启时写入 `CV_USER`/`CV_PASS` 环境变量 |
| `CV_APP_DIR` | `<repo>/app` | 静态站点目录（自启用） |

- 退出码：`0` = 全部断言通过（允许有 SKIP，见第 9 节）；`1` = 有失败断言、端点未断言或执行异常。
- 自启模式会在 8090 端口空闲时启动独立进程；8090 已有 CertVault 时自动复用（此时无 `CV_DATA`，磁盘与 secret 相关断言转为 SKIP）。
- 每次运行会先把当前台账备份到服务器 `backup/`（EP04 前），失败时可人工回滚。

## 5. ② 三角色越权矩阵

契约 §11.1：viewer 只读；editor 可写业务数据；admin 额外管理账号。服务端 `requireRole` 统一返回 403 `forbidden`。

| 路由 | viewer | editor | admin（额外覆盖） |
|---|---|---|---|
| `PUT /api/records` | 403 ✅ | 200 ✅ | 200 ✅ |
| `PUT /api/settings` | 403 ✅ | 200 ✅ | — |
| `POST /api/images/{recordId}` | 403 ✅ | 200 ✅ | — |
| `DELETE /api/images/{recordId}/{file}` | 403 ✅ | 200 ✅ | — |
| `DELETE /api/images/{recordId}` | 403 ✅ | 200 ✅ | — |
| `POST /api/backups` | 403 ✅ | 200 ✅ | — |
| `POST /api/lock` | 403 ✅ | 200 ✅ | — |
| `DELETE /api/lock` | 403 ✅ | 200 ✅ | — |
| `GET /api/admin/users` | 403 ✅ | 403 ✅ | 200 ✅ |
| `POST /api/admin/users/{id}/approve` | 403 ✅ | 403 ✅ | 200 ✅ |
| `POST /api/admin/users/{id}/reject` | 403 ✅ | 403 ✅ | 200 ✅ |
| `POST /api/admin/users/{id}/role` | 403 ✅ | 403 ✅ | 200 ✅ |
| `POST /api/admin/users/{id}/status` | 403 ✅ | 403 ✅ | 200 ✅ |
| `POST /api/admin/users/{id}/reset-password` | 403 ✅ | 403 ✅ | 200 ✅ |

计数说明：任务书写「viewer 对 12 个写接口全部应 403」。按当前契约/实现，editor 级写接口 8 个、admin 独占写接口 5 个（共 13 个写路由），另有 admin 读接口 1 个；脚本按超集断言 14 条，全部通过，不存在漏测。

矩阵断言在脚本中输出为 `矩阵[viewer]` / `矩阵[editor]` / `矩阵[admin]` 前缀的独立 PASS/FAIL 行，并额外做汇总断言（viewer=14、editor 写=8、editor admin=6、admin=6）。

## 6. ③ 注册 → 审批 → 角色生效 → 拒绝 → 停用 全流程

1. `POST /api/register` 建 pending 账号（EP22），`register/status` 可轮询（EP23）。
2. pending 账号登录 → 403，提示「等待管理员审批」。
3. admin `GET /api/admin/users` 能看到 pending（EP24，且响应不含口令散列）。
4. admin `approve{role:editor}` → active（EP25）；该账号用原密码登录，`role=editor`。
5. 另建账号走 `reject{reason}` → rejected；status 返回原因；登录 403 且 message 含原因（EP26）。
6. 同一 token 的角色即时生效：viewer 写 403 → 提升 editor 后 200 → 降回 viewer 后 403（EP27）。
7. 停用：`status{disabled}` → 登录 403 带原因、既有 token 立即 401（EP28）。
8. 重置密码：旧 token 全部 401（tokenVersion 递增）、新口令可登录（EP29）。

## 7. ④ 并发写（双 token 各 20 次）

- 准备：admin 读当前台账，取 `updatedAt` 作为同一 `If-Match`；editor 与 admin 两个 token 各发 20 次 `PUT /api/records`，请求体各自追加一条带唯一 id 的记录（`r_conc_a_i` / `r_conc_b_i`），全部并发发出。
- 断言 1：至少 19 次 `409 conflict`（服务端写队列串行 + ETag 前置条件，实测 **39 次 409 / 1 次 200**），且无非 200/201/409 的状态（无网络错误、无 5xx）。
- 断言 2：最终 `GET /api/records` 为合法 JSON：`version=1`、`updatedAt` 为字符串、每条记录 `id/name` 完整、包含并发写入的标记记录。
- 断言 3：磁盘 `$CV_DATA/data/certvault.json` 可直接 `JSON.parse`（自启或提供 `CV_DATA` 时执行）。
- 断言 4：`$CV_DATA` 递归扫无 `.tmp` 残留（原子写 tmp+rename 无泄漏）。

## 8. ⑤ 会话：86400 过期与 extend 续期

- 登录体 `ttlSeconds=86400`：token payload `exp-iat=86400`，`/api/session.ttlSeconds=86400`。
- 过期判定：用 `config.json.secret` 伪造同 payload 的已过期签名 token（`exp=now-10`）→ 401 `unauthorized`；再伪造未过期签名 token → 200，证明 401 来自过期判断而非签名失败（未提供 `CV_DATA` 时该项 SKIP）。
- `POST /api/session/extend{ttlSeconds:172800}`：返回新 token，`exp-iat=172800`、`/api/session.ttlSeconds=172800`、新 token 可用、旧 token 仍可用（EP20）。
- 登出：`POST /api/logout` 200，该 token 立即 401，`Set-Cookie` 清空（EP03）。

## 9. 环境差异与 SKIP 规则

| 场景 | 行为 |
|---|---|
| 自启（默认） | 全量 84 条断言；临时数据目录跑完删除 |
| `CV_BASE` 外部服务 + 未给 `CV_DATA` | 跳过「伪造 token 过期对照」「磁盘 JSON」「`.tmp` 扫描」；汇总标注 SKIP，退出码仍为 0 |
| `CV_BASE` 外部服务 + 给了 `CV_DATA` | 全量断言 |
| 注册限流 | 同一 IP 10 分钟最多 5 次注册；本脚本一轮恰好用满 5 次 |

## 10. 已知限制与复跑注意

1. **重复运行**：若对一个长期运行的服务器 10 分钟内二次执行，注册名额已耗尽，矩阵中「待审批账号」创建失败，admin 用户管理矩阵会记为 SKIP 而非 FAIL；重启服务或等待 10 分钟即可恢复全绿。
2. **端口占用**：默认自启需要 8090 空闲。若已有 CertVault 占用，脚本会复用该服务；要跑全量（secret/磁盘断言）请显式提供 `CV_DATA`，或先停掉旧实例、或换 `CV_BASE` 指向独立实例并给出其数据目录。
3. **伪造 token 用例依赖本机可读 `config.json`**；NAS 容器内路径不同时，通过 `CV_DATA` 指向卷映射目录。
4. **计数口径**：任务书的「12 个写接口」与契约 §11.1 的实际路由数（editor 8 + admin 5）略有出入；脚本按超集覆盖 14 条（含 admin 读接口），不存在漏测。
5. **审计上报**：`POST /api/audit` 在实现中要求 viewer 及以上（用于客户端补记 `record_export/import/password_change`），不属于「写业务数据」的越权面，故未计入 viewer 403 矩阵。
6. **普通账号审计过滤**：非 admin 的 `?action`/`limit` 参数按契约被忽略，固定返回本人最近 50 条；脚本按此断言，不把它当缺陷。
7. **时间精度**：token `iat/exp` 为秒级，脚本比较 `exp-iat` 的整秒差，不依赖挂钟绝对时间。
